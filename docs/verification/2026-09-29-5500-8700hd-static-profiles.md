# 5500 and 8700HD static profiles — 29 September 2026

> **Evidence status:** Implementation and local verification record without hardware. The 5500 1.2.8.24 and 8700HD 1.0.2.161 profiles are derived from the official PC Remote and firmware and cross-checked against the factory presets in the same installers. Every check below ran against automated tests or a local protocol simulator, not against a processor.

## Implemented boundary

- The exact banners `5500 V 1.2.8.24` and `8700HD V 1.0.2.161` select writable adapters with `Evidence::Static`. They enable parameter writes, preset recall and live meters. Other firmware on the same model remains read-only.
- Each profile embeds its own parameters, processing pages and meter layout. The interface loads them again whenever the adapter changes. The 5700i keeps its built-in reference pages and meters.
- A write requires the live field, the profile value at the current index, and an unchanged host, session and preset. Every static write is followed by a full AP/AS readback. On a mismatch the processor value is shown, an error is reported, and nothing is retried.
- Preset recall, the recall fallback read and preset-file application now use the detected model's terminal banner and document family. Before this change they were hard-coded to the 5700i.
- In the macOS app, System Settings for a model with its own profile opens the generic Setup workspace instead of the 5700i-specific native window.

## Verification run

- `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all -- --check`: passed. New tests cover:
  - exact-banner write enablement and read-only neighbouring firmware;
  - an embedded profile, pages and meters for every writable adapter;
  - 5500 and 8700HD wire values, including a ×100 transform and excluded fields;
  - the 8700HD terminal banner and document family;
  - a simulated 5500 write confirmed by readback, and a simulated mismatch that shows the processor value without a retry.
- `node --experimental-strip-types --test packages/ui/tests/*.test.ts`: 48 passed, including profile meter models (variable record length, curves, FM/HD filtering) and profile pages (unique titles, no lost controls).
- `npm run build --prefix packages/ui` and `python3 scripts/check-docs.py`: passed.
- A local simulator that speaks the PC Remote framing and terminal commands with each banner was used with the running service and headless Chromium at 1440×900:
  - 5500: 89 processing and 121 system fields, a preset list, 13 pages and 10 meter groups with live bars;
  - 8700HD: 23 pages including HD, and 16 meter groups;
  - a processing write through the API became `modif EXTREME` with the value confirmed by readback;
  - a system write and a recall of another preset were confirmed.
- Not run in this Linux environment: the Swift test programs and the macOS app bundle. The Swift changes only add the 8700HD to the model enumeration, network discovery and its test table.

## Not verified

Behaviour on a real 5500 or 8700HD: whether the firmware accepts every written value, meter calibration, a busy or second client, reconnect, and long sessions.
