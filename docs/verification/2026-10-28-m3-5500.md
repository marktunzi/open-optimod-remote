# M3: original 5500 1.2.8.24, 28 October 2026

> **Evidence status:** static. Read from the 5500 firmware 1.2.8.24 (`_optimod.exe`) and `5500PC.exe` 1.2.8.24, each compared with the 5500i firmware and client, whose opcodes were captured on firmware (M2). Covered by unit tests against a scripted unit. No 5500 exists here, physical or virtual: **real-firmware confirmation is BLOCKED**, not the implementation. No physical processor was touched. Protocol table: [docs/protocol/5500.md](../protocol/5500.md).

## Implemented

| Gap | Evidence | Change |
|---|---|---|
| Sync of a real 5500 would fail: the app accepted only `8300.` documents, but the firmware writes `5500.50` | the only version string in the 5500 firmware is `5500.50`; `8300.10` is the installer's factory family | both families accepted for the 5500 |
| Save, Save As, Rename and Delete went to the terminal (`SP`/`DP`) | the client uses file messages: 229 upload, Delete ECh | 5500 wire `preset_file_delete = ECh`; terminal path no longer used |
| Automation, Security, Diagnostics missing | firmware switch: F1h→EAh automation, F3h→E6h passcodes; client sends CCh at sync | `tool_files` with the 5500's own opcodes; automation file opcode per model (5500 EAh, 5500i EBh), automation delete with the model's delete opcode |
| Backup to PC, Restore from PC missing | client Backup EFh F2h F1h; Restore per file name | 5500 backup of setup, automation, user and setup presets; restore sends `Automation.orb55autom` as EAh, the rest as 231 |
| Access levels were full-or-read-only | client menu update handlers: the 5500i's bounds | 5500 uses the 5500i's levels (Delete ≤1) |
| No System Settings layout | client property sheet: 8 tabs | `profiles/5500/1.2.8.24/system-layouts.json` in the client's order; parameters, pages and meters untouched |
| Native Presets had no Back Up / Restore of the unit's files for the 5500 | as above | `PresetFileFormat` gates include the 5500 (no network file) |

Shared with the 5500i (same client and firmware code, opcodes one lower): the native Presets, Automation, Security, Diagnostics and System Settings windows, upload headers (FILETIME), readback loops and error messages.

Changed for the 5500i too, from its client's Restore code: `Automation.orb55autom` is restored as EBh and `Network.orb55net` as EAh, not as 231. The M2 capture restored only a user preset and `Setup.orbsetup` (both 231), so it does not cover these two files: **UNTESTED on firmware**.

## Tests

- `the_5500_wire_is_the_5500i_wire_one_opcode_lower` (orban-protocol)
- `the_5500_profile_differs_from_the_5500i_where_its_client_does`: no COMPOSITE MODE on Final Clipping, 79 meter values with MPX Power on 77 (86/84), 8 Setup tabs (10), own reference ids
- `document_families_are_parsed_only_for_the_detected_processor`: 5500 accepts 5500.50 and 8300.10
- `the_5500_and_5500i_clients_delete_only_at_level_1_or_lower`
- `the_5500_tools_backup_and_restore_use_its_own_opcodes` (orban-web): F3h/F1h reads, CCh at sync, ECh deletes, backup EFh F1h F2h, restore EAh + 231, none of the 5500i's F4h/EDh/FBh/F0h
- `PresetsAPITests`: 5500 restore sorting, no network file
- Removed: three tests of the 5500 terminal `SP`/`DP` path, which the app no longer uses

Results: `cargo test --workspace` all pass (orban-web 78), clippy and fmt clean, `PresetsAPITests passed`, macOS app builds without warnings.

## BLOCKED: needs a running 5500

- Login with the real answer (with or without the session line) and a full sync.
- Whether the unit answers a 229/231 upload with an extra FAh, as the 5500i does with FBh. The app assumes it does (shared code); if not, a Save or Restore is reported as unconfirmed after the receive deadline.
- Automation, Security and Restore round trips; System Settings writes and readback; meters under signal.
- Native-app screenshots: none, because there is no unit to connect to.
