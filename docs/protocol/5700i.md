# 5700i interoperability notes

Reference: device firmware 3.0.1.20, document version 5700.51, matching Windows PC Remote SHA-256 `63def9bbe3ea4cc5714b958a330f511e9f8540b973f0cedaf596dd7956054b43`. Analysis uses a locally installed reference; no proprietary program is distributed or required at runtime.

## Session and framing

PC Remote uses TCP 6201. Login is `connect`, LF, the legacy-obfuscated uppercase access code, LF, NUL. The access-code transform starts with state 123456 and updates `(state * 419 + 6173) % 29282` per byte. XOR with the low byte, preserving a byte that would become zero. This is legacy obfuscation, not transport security. The current implementation intentionally supports only tested ASCII access codes.

Successful login returns four LF-separated lines: success marker, access level, model/firmware and session seed. Failure responses can terminate with NUL. Access level zero was tested. Other write permission levels remain disabled.

Every subsequent frame has a five-byte header and a 1–65535 byte body. For body-length bytes `hi`, `lo`, header bytes are `hi ^ 0x1a`, `-hi ^ 0xc2`, `lo ^ 0x67`, `-lo ^ 0xa8`, and the negative sum of those four bytes, with byte wrapping. Validate both complement pairs and the checksum. Do not attempt recovery from corrupt framing on a live control connection.

The body starts with two eight-character decimal fields: opcode minus 204 and protocol type 6. Known operations:

| Request | Meaning | Response |
|---|---|---|
| 218 | Disconnect | Connection closes |
| 219 | Poll / heartbeat | 220, or subscribed meter frames |
| 222 / 223 | Enable / disable session meters | Subscription state |
| 227 | Typed parameter change | Ordered 250/251 boundary; exact readback when required |
| 239 | Fetch on-air archive | 229 |
| 240 | Fetch setup archive | 233 |
| 250 | Ordered response boundary | 251 |

Do not infer that other opcodes are read-only. In particular, 226 and bulk preset operations have save/flush side effects and are not used by this development UI.

## Changes and confirmation

A parameter change is `NAME;INDEX;TYPE:VALUE;SCOPE;`. Scope 1 is processing; 2 is system. Examples use synthetic values or a non-audio control. `CONTRAST;2;Int:2;2;` changes display contrast to index 2. Its allowed indices are 0–3, not 0–4. String types use angle delimiters, such as `String:<Independent>;`.

A response boundary confirms that the PC Remote stream has processed everything before it; it is not a field-by-field terminal document. Interactive single-field writes first compare host, session, preset and prior field against the app's last confirmed document, send opcode 227 once, then require the 250/251 boundary and update that guarded cache. If the boundary fails, the independent terminal status interface reads actual processing (`AP [code]??`) or system state (`AS [code]??`) to resolve the outcome. Fields outside the hardware-verified profile (the statically derived supplement in `profiles/5700i/3.0.1.20/static-parameters.json`, such as the two-band and MX structures) always take that exact readback, even after a successful boundary. Manual refresh, preset export/application and explicit hardware verification also use exact documents. A timeout has an unknown outcome and must not trigger an automatic retry.

Do not take AP/AS snapshots before and after every successful interactive write. On the reference firmware each full terminal document suspended live meter responses for roughly 570 ms. Removing those routine snapshots reduced the measured write-related meter gaps from two pauses of about 568–600 ms to 103–189 ms, the remaining interval being the processor's own opcode-227 work. The canvas keeps interpolating the last real packets during that short interval; it never invents signal values.

On the reference Mac and device, the standalone native check changed contrast 3 → 2 → 3 and verified that all 222 processing and 178 system fields matched the baseline afterwards. The same check passed through browser keyboard input. A later reversible processing check changed `B2 OUTPUT MIX` by 0.1 dB and restored it with exact readback while the session and meters remained live. Routing, coupling, Recall, text and firmware writes have not been hardware-verified.

## Meter messages

Response 228 contains a raw bank byte, decimal count followed by LF, and that many binary bytes. The observed profile has 112 channels per bank. Banks 1 and 2 must **not** be interpreted as FM and HD: both contain channels from both processing paths. The UI converts bank 1 with channel-specific reference curves; see [meter conversions](../meter-curves.md). Current/peak bank semantics, some absolute HD/loudness axes and every indicator still require reference comparison.

Verified reference channel identifiers include input L/R 1/2, AGC bass/master L 3/4, FM bands 1–5 L 5–9, FM output L/R 27/28, HD bands 1–5 L 39–43, and HD limiting L/R 19/20. Other channels, right-channel gain reduction, gate flags, output scales and peak behavior remain part of the parity work.

A native 30-second test received 286 frames from each bank, with 256 changing frames in each bank; the slowest observed poll cycle was 219 ms. A later UI-path measurement averaged 55.3 ms between distinct frames and showed that requesting every 25 ms did not increase the processor's output rate. The runtime therefore polls every 50 ms and interpolates display motion between real packets. These are smoke tests, not the required eight-hour soak or a Windows latency comparison.

## Archives

File bodies contain two decimal timestamp words, filename/path metadata and byte count, each LF-delimited, followed by exactly the specified binary data. Firmware 3.0.1.20 can return Windows-style absolute paths and can emit an empty filename for a preset-change event. These are accepted as bounded metadata but are never resolved or used as local paths or filenames.

Observed archives use AES-256 CBC with ciphertext stealing for a partial last block, prefixed by a 16-byte IV. The access code is repeated to form the 32-byte key. This scheme does not authenticate content. Decrypted documents must pass structural checks; successful decryption alone does not establish integrity.

Documents contain typed fields with device indices. Keep Cent values as integer hundredths, preserve enum indices and retain original metadata. The embedded 366-field profile was derived from static pure conversion routines and cross-checked against current device values. It is not a complete specification of visibility, coupling, defaults for all algorithms, or optional hardware.

## Equalizer value conversions and units

Reference conversion routines establish these index-to-wire mappings. Values below are wire values; `Cent` is divided by 100 for display. No Windows executable is needed at runtime.

- Low bass frequency: 35 integer values, 80–145 in steps of 5, 150–240 in steps of 10, 250–330 in steps of 20, 350–500 in steps of 30.
- PEQ low frequency: 47 values, `Cent(10 * trunc(200 * 25^(index/46)))`, displayed in Hz.
- PEQ mid frequency: 46 values, `Int(trunc(250 * 24^(index/45)))`, displayed in Hz.
- PEQ high frequency: 39 values, `Cent(10 * trunc(10 * 15^(index/38)))`, displayed in kHz.

FM and HD use the same frequency conversions. Reference identities: low bass 0x48d850, PEQ low 0x48c880, mid 0x48c8f0, high 0x48c950. The numeric conversion truncates toward zero. Static ranges are embedded so runtime math-library differences cannot alter a transmitted value. The current device values were cross-checked; exhaustive hardware sweeps and an interactive Windows comparison remain outstanding. Numeric units are retained separately from wire values and never appended to choice labels such as Off.

## Preset catalog and recall

The catalog exchange sends authenticated LP followed by AP on one connection. The complete AP document marks the response boundary, avoiding idle-time heuristics on a fragmented preset list. Recall validates the requested name and expected on-air identity against that session-owned catalog/document; it does not repeat LP/AP immediately before the write. It sends documented `RP NAME[CODE]` followed by AP in one terminal transaction, requires an `ON AIR: NAME` acknowledgment and a matching AP document, and publishes that returned document directly as the new processing state and comparison baseline.

Do not send 50 ms PC Remote heartbeat/meter polls while the RP/AP transaction is switching the processor. The 5700i can stall those replies and make an otherwise healthy session accumulate receive timeouts. After the complete AP document arrives, send opcode 222 once to re-enable session meters and reset the normal polling interval so its first tick occurs 50 ms later. Selection alone sends no write. Errors never trigger retries. If the combined response is unusual, one direct AP read while polling remains paused determines whether the selected preset is on air.

## Local preset export and application

The app exports a fresh validated AP document as a locally named `.orb57user` file. It does not use an undocumented named-save opcode. Applying a local file parses the complete document, validates every imported field against the active firmware profile, checks host/session/current-preset guards, orders `HD COUPLING` ahead of dependent HD fields and writes each field once with opcode 227. It then reads the full AP document up to four times without replaying a write and requires every imported field to match exactly. Only a fully confirmed document becomes the new modified-state comparison baseline.

FM→HD coupling is not a blanket lock on every HD-named field. Per the official 5700i 3.0 Operating Manual, coupled presets make the HD equalizer and multiband compressor/limiter controls follow their FM counterparts, while the five controls in PC Remote's **HD Limiting** page remain independent: `IBOC EQ GAIN`, `IBOC EQ FREQ`, `IBOC LIM DR`, `HD DE ESS`, and `HD COUPLING`. The UI keeps that page available in coupled mode and preset import continues to write and verify those five fields.

This does not establish the named on-device Save, Save As, rename, delete, previous-preset or bulk backup commands. Opcode 226 remains unused.

## Additional parameter conversions

- AGC BASS COUPLE: index 0 is Choice Off; indices 1–13 are Int(13-index), unit dB (reference 0x490650).
- Both BS1770 LDNES CTRL THR fields: indices 0–200 become Cent((index-310)*10), unit dB (0x498070).
- DIVERSITY DELAY ADJ for the supported 5700i: indices 0–0xf833d become a Choice string formatted to nine decimals: (index+23361)/64000 seconds (0x4986d0, model branch 2; count initialized at 0x4ab0ff). UI entry snaps to one supported sample.
- Identity integer port ranges and RDS UECP site numbers are represented compactly rather than by enormous enumeration arrays.

Text changes retain their existing index and use UserString, reject delimiter/control/non-ASCII characters and validate fresh readback. Domain-specific validation beyond wire encoding is not yet exhaustive for all RDS and remote-contact text workflows.
