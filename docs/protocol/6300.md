# 6300 interoperability notes

Reference: original OPTIMOD 6300 firmware 4.1.1.19 (document version 6300.50) running in the Optimod emulator. Probed on 21 October 2026.

The login answers `6300 V 4.1.1.19`; the status port answers `Orban Optimod 6300 V 4.1.1.19`. A factory 6300 has no access code until one is created; the scratch unit used for these tests had one. The opcodes are the 8700HD generation ([8700HD notes](8700hd.md)):

| Purpose | Request | Answer |
|---|---|---|
| Response boundary | 249 (F9h) | 250 (FAh); FAh alone is not answered |
| On-air file | 238 (EEh) | 229 `OnAir.orb63onair` |
| Setup file | 239 (EFh) | 232 (E8h) `Setup.orb63setup` |
| User preset files | 242 (F2h) | one 231 (E7h) per `.orb63user` file |
| Password file | 243 (F3h) | 230 (E6h); never requested by the app |

240 (F0h), 241 (F1h) and 244 (F4h) are not answered. Meter records carry bank 1 and 111 values.

A user preset may have a factory preset's name: the test unit had `CRISP.orb63user` next to the factory CRISP. The terminal `LP` lists both as `factory`. The app lists the user one as "CRISP (user)"; on air the unit reports CRISP for either. A Recall upload ends with FAh, which the unit answers (the Recall completed without waiting for the boundary deadline).
